# Security Policy

## Supported versions

| Version | Security updates |
|---|---|
| 2.0.x | Supported |
| Earlier releases | Upgrade required |

## Reporting a vulnerability

Use the repository's **Security** tab and select **Report a vulnerability**
to open a private report. Do not include vulnerability details in a public
issue, discussion, pull request, or social media post.

If private vulnerability reporting is unavailable, contact the repository
owner through the GitHub profile and request a private channel. Do not send
exploit details until a private channel has been established.

Please include:

- the affected NetRecon version and operating system
- the feature or file involved
- clear reproduction steps using a safe local target
- the expected and observed behavior
- the security impact
- suggested remediation, if available

Remove credentials, private keys, customer information, private network
addresses, and real scan results before submitting evidence.

## Research boundaries

Use only systems and networks you own or are explicitly authorized to test.
Do not run extended Nmap profiles against public or third-party targets for a
report. A minimal local proof is preferred.

Reports will be reviewed before any public disclosure. Credit can be included
in the advisory when requested and when doing so does not expose private
information.
